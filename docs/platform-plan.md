# 수원 산업관광 플랫폼 구성안

## 1. 서비스 모델

공급 데이터 등록 → 기업 조건 선택 → AI 추천·일정 편집 → 컨벤션센터 신청 → 센터 검토 → 관광기업 연결 → 견적·일정 조율 → 확정.

추천은 예약이 아니다. 신청의 수신·조정 주체는 컨벤션센터이며, 관광기업이 연결된 후 수용 가능 여부, 교통, 통역, 비용을 조율한다. 현재 모든 화면은 기획 예시이며 실제 연락을 수행하지 않는다.

## 2. 화면 및 역할

| 화면 | 핵심 정보·행동 |
| --- | --- |
| 홈 | 플랫폼 소개, 등록 시설·상품 탐색, 맞춤 일정 시작 |
| 조건 선택 | 기업 연구 분야·목적, 날짜, 인원, 희망 장소, 출도착 지점, 관광 스타일, 등록 프로그램·상품, 통역 |
| 추천 결과 | 시설·상품 이름, 추천 근거, 날짜별 일정, 이동 시간, 조정 필요 상태, 대안·순서 변경 |
| 신청 | 회사·담당자, 일정 버전, 요청·예산, 개인정보·운영사 전달 동의, 센터 접수 |
| 신청 현황 | 접수·검토·보완·연결·조율·확정 상태, 담당자 응답, 변경·취소 |
| 센터 운영 | 시설·프로그램·상품·운영사 등록, 검증·게시, 신청 검토, 운영사 배정, 변경 이력 |

기업은 자신의 신청만 열람한다. 센터 운영자는 데이터와 신청을 관리한다. 관광기업에는 연결된 신청의 승인된 정보만 전달한다. 실제 역할별 화면 접근 제어는 서버에서 구현해야 한다.

## 3. 등록 데이터 모델

| 엔터티 | 주요 필드 |
| --- | --- |
| Facility | id, 이름, 지역, 주소, 좌표, 연구 태그, 설명, 출처, 검증일, 공개 여부 |
| Program | id, facility_id, 연구 태그, 프로그램명, 소요 시간, 최소·최대 인원, 운영 요일·시간, 휴무·예외, 사전신청 기한, 언어, 방문 제한, 검증 상태 |
| TourismProduct | id, 운영사 id, 장소·좌표, 스타일 태그, 소요 시간, 수용 인원, 일정·언어·비용 조건, 게시 여부 |
| Operator | id, 업체명, 담당자, 활동 지역, 전문 분야, 언어, 규모, 승인 상태 |
| Itinerary | id, 기업 조건, 일정 버전, 선택 시설·상품 id, 순서·시간, 추천 근거, 제약 검증 결과, 데이터 기준 시각 |
| Application | id, 기업·담당자, itinerary_version, 날짜·인원·요청, 센터 담당자, 상태, 동의 기록 |
| Connection | application_id, operator_id, 전달 항목, 연결 담당자·시점, 견적·조정 이력 |

시설과 그 시설이 실제 제공하는 프로그램을 분리한다. 연구 태그가 맞아도 방문 프로그램이 등록되지 않은 시설은 방문 일정에 넣지 않는다. 예약 가능 여부가 확인되지 않은 데이터는 '조정 필요'로 표기한다.

## 4. AI 추천 처리

1. 입력 검증: 날짜, 인원, 연구 분야, 관광 스타일, 선택 상품, 장소, 출도착 조건을 구조화한다.
2. 후보 필터: 검증·공개된 프로그램과 상품만 조회하고 인원, 운영일, 언어, 방문 제한, 사전신청 기한을 적용한다.
3. 관련도 계산: 기업 연구 분야와 프로그램 연구 태그, 선택 상품과 관광 스타일의 관련도를 평가한다. 점수 가중치는 실제 데이터로 조정한다.
4. 일정 구성: 고정 시간 프로그램을 우선 배치하고 이동·식사·휴식 시간을 확보한다. 이동 시간은 검증된 경로 데이터 또는 운영자 입력을 사용하며 없는 값을 확정값으로 만들지 않는다.
5. 결과 검증: 모든 항목의 id가 등록 데이터에 존재하는지, 영업시간·인원·시간 겹침·이동 여유·선택 상품이 충족되는지 검사한다.
6. 설명: 생성 AI는 검증된 후보와 일정에 대한 추천 이유·요약을 작성한다. 존재하지 않는 시설, 프로그램, 가격, 예약 가능성을 생성하지 않는다.
7. 대안: 충족 후보가 없으면 부족 조건과 완화 선택지를 안내하거나 센터 검토로 넘긴다. 사용자가 수정하면 다시 검증한다.

추천 결과와 신청 시점 사이 데이터가 변경되면 신청 일정 버전을 보존하고 재확인을 요청한다. 외부 상품 설명은 자료로만 처리하며 모델 지시문으로 실행하지 않는다.

## 5. 상태와 연결 업무

`접수 → 센터 검토 → (보완 요청 ↔ 보완 제출) → 관광기업 연결 → 견적·일정 조율 → 확정`

연결 실패는 대체 운영사 검토로, 수용 불가는 대체 프로그램 조율로 처리한다. 취소·거절은 종료 상태로 기록한다. 운영사 연결은 센터 담당자가 선정하고 연결 내역을 기록하는 업무이며, AI가 자동 예약하거나 계약을 체결하지 않는다.

## 6. 단계별 개발 범위

- 현재: 편집 가능한 Figma 구성안 6개, 동일 콘텐츠 웹 뷰어, 기존 일본어 초기 데모.
- 다음 MVP: 등록 데이터 저장·관리, 제약 기반 추천 엔진, 결과 수정, 신청 저장, 센터 검토·연결 관리, 기업/운영자 인증·권한.
- 후속: 검증된 일정의 생성 AI 설명, 지도 이동 시간, 운영사 포털, 다국어, 일정·견적 변경 알림.

실제 시설·프로그램 목록, 수용 조건, 운영사 목록, 센터 담당자와 운영 정책을 확보해야 실데이터 추천과 신청 업무를 연결할 수 있다.
